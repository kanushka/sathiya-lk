# Sathiya v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Sathiya v1 — public website, school admin app (setup + timetable editor + print), teacher mobile view, super admin — on Firebase.

**Architecture:** pnpm monorepo. `packages/core` holds all domain types and pure timetable logic (clash detection, availability, progress, publishing snapshots) and is the single source of truth used by the app and Cloud Functions. `apps/app` is a React SPA reading Firestore directly under security rules; privileged writes (accounts, claims, entries, publish) go through callable Cloud Functions in `functions/`. `apps/web` is a static Astro site.

**Tech Stack:** TypeScript 5, pnpm workspaces, Vitest, React 18 + Vite + react-router 6, Tailwind CSS 3, i18next + react-i18next, Firebase JS SDK v10 (Auth, Firestore, Functions, Storage), Firebase Functions v2 (Node 20) + firebase-admin, @firebase/rules-unit-testing, Astro 4, Playwright, qrcode.

**Spec:** `docs/superpowers/specs/2026-11-21-sathiya-design.md` (read §6a — it overrides earlier sections). Screens: https://claude.ai/artifact/Hba3wEy5peivzGi4rAxD96 (layout source of truth; colours, copy, spacing).

## Global Constraints

- Node 20, pnpm 9, TypeScript `strict: true`.
- Firebase project id `sathiya-lk`; web config values exactly as in spec §5 (website appId `1:591171596099:web:f4363f68c921388b0489f6`, app appId `1:591171596099:web:6d617b8424ab69cd0489f6`).
- Hosting targets: `web` → website, `app` → admin/teacher app.
- Sathiya palette: teal `#0E6B6A`, navy `#14213D`, saffron `#F2A541`, ground `#FBFAF7`. School screens use school `colors.primary` / `colors.second` via CSS variables `--brand`, `--brand-2`, `--on-brand`.
- Fonts: Inter + Noto Sans Sinhala (Google Fonts).
- Languages `en`, `si`; every user-visible string goes through i18n; data with two names falls back to English when Sinhala is empty.
- Admin screens desktop only (min 1024px); teacher views and login responsive down to 360px.
- Add/edit forms are centred modals. Admin sidebar collapsible to 72px icon rail, state in localStorage `sathiya.sidebar`.
- NIC is never collected or stored.
- Teacher passwords: random 6 digits from `crypto.randomInt`; synthetic email `${staffId.toLowerCase()}@${schoolId}.teachers.sathiya.lk`.
- Staff ID = school prefix (2–5 uppercase letters) + 3-digit number, e.g. `SCC024`.
- Week Mon–Fri; days indexed `0..4`.
- Every package/app has `pnpm test` (Vitest); root `pnpm test` runs all; functions and rules tests run against the Firebase emulator via `pnpm test:emulators`.
- Commits: one line, Conventional Commits, no AI attribution.

## Review Focus

1. **Classes on different templates** — a teacher with 6A (default, P3 09:10–09:50) and 1A (Primary, P3 09:00–09:40) must be shown busy; a class on Primary must not be offered for a default-row slot it doesn't overlap. Tests: Task 0.3 `findConflicts` overlap cases, Task 0.4 `classOptionsForTeacherSlot`.
2. **Two admins editing at once** — concurrent `saveEntry` calls placing one teacher in two classes at the same time: exactly one succeeds. Test: Task 1.3 concurrency test.
3. **Editing an existing entry** — re-saving an entry with a new teacher must not clash with itself. Test: Task 0.3 `excludes the entry being edited`.
4. **Empty Sinhala names / missing translations** — UI shows English, never blank or a key. Test: Task 0.2 `pickName falls back`, Task 0.6 i18n fallback test.
5. **Deleting setup data in use** — deleting a subject used in the draft is refused with the count. Test: Task 0.4 `usageCount`, Task 1.2 `deleteGuard` rules/callable test, Task 3.3 UI test.
